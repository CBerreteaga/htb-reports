Summary

Devel is a beginner-friendly Windows machine that demonstrates the security risks of default or weak service configurations. The machine exposes FTP with anonymous login enabled, and the FTP directory appears to map directly to the web server directory. This allows an attacker to upload an ASPX web shell and gain an initial foothold. Privilege escalation is then performed using a local Windows kernel exploit.

Initial Foothold

After initial enumeration, ports 21 and 80 were found open. Port 21 was running FTP and allowed anonymous login. Since the FTP directory appeared to be connected to the IIS web root, I tested whether uploaded files could be accessed through the browser.

After confirming that files uploaded through FTP were reachable over HTTP, I identified that the web server could execute ASPX files. I then used msfvenom to generate an ASPX Meterpreter reverse shell, uploaded it through FTP, and triggered it by visiting the file in the browser. This provided an initial Meterpreter session on the target.

Privilege Escalation

After gaining an initial shell, I used Metasploit's local exploit suggester module to identify possible privilege escalation paths on the compromised system. 

post/multi/recon/local_exploit_suggester

The local exploit suggester returned several possible exploits. The first suggested module was: 

exploit/windows/local/bypassuac_comhijack

This exploit failed because the current user did not have the required permissions. The next suggested module was: 

exploit/windows/local/bypassuac_eventvwr

This also failed for the same reason. Another suggested exploit was: 

exploit/windows/local/cve_2020_0787_bits_arbitrary_file_move

This exploit was not compatible with the target system. Finally, the following module was tested: 

exploit/windows/local/ms10_015_kitrap0d

This exploit worked successfully and returned a session as: 

NT AUTHORITY\SYSTEM

Vulnerabilities / Misconfiguration

The main misconfiguration on this machine was anonymous FTP access. Even worse, the FTP directory appeared to be mapped to the IIS web root, allowing uploaded files to be accessed from the browser. Because IIS supports ASPX execution, this allowed a malicious ASPX file to be uploaded and executed on the server.

The system was also vulnerable to an older Windows privilege escalation exploit, MS10-015, which allowed the attacker to escalate privileges to NT AUTHORITY\SYSTEM.

Defensive Takeaways

Anonymous FTP access should be disabled unless absolutely required. If FTP must be used, uploaded files should not be placed inside a web-accessible directory. Web servers should also restrict executable file uploads such as ASPX, PHP, or other server-side scripts.

The system should also be kept fully patched to prevent known local privilege escalation vulnerabilities from being exploited. Proper file upload restrictions, least privilege, and regular vulnerability scanning would have reduced the risk on this machine.

Lessons Learned

This machine helped reinforce the importance of checking how services interact with each other. FTP by itself may not always lead to code execution, but when it is connected to a web server directory, it can become a serious vulnerability.

I learned how to use msfvenom to generate a payload that matched the target web server. Since the server was running IIS and could execute ASPX files, I was able to create an ASPX reverse shell, upload it through FTP, and trigger it from the browser.

I also learned how to use different modules within Metasploit Framework. After getting an initial session, I used a handler to catch the reverse shell, the local exploit suggester module to identify possible privilege escalation paths, and then tested different local exploit modules until one successfully gave SYSTEM access.

Not every suggested exploit will work, so it is important to understand why an exploit fails and continue testing other options.
