Executive Summary

Fireflow exposed an HTTPS web application that led to a public Langflow instance on flow.fireflow.htb. The Langflow instance was vulnerable to an unauthenticated code execution path through the public flow build endpoint. This allowed initial command execution as www-data and a reverse shell on the host.

Post-exploitation enumeration revealed Langflow environment variables containing a superuser password. That password was reused by the local Linux user nightfall, allowing SSH access and retrieval of the user flag. Further enumeration exposed an MCP AI Tool Registry running behind Kubernetes/NodePort. The MCP service disclosed JWT support for the insecure none algorithm, allowing an unsigned JWT to be forged with role=admin. Admin access allowed registration of MCP tools, leading toward RCE inside the MCP pod and a Kubernetes nodes/proxy abuse path to root.

Phase 3: Initial Access - Langflow RCE

Vulnerability Summary

Langflow 1.8.2 was vulnerable to an unauthenticated code execution issue in the public temporary flow build endpoint. The application accepted attacker-controlled flow JSON data and executed Python component code during flow construction.

Key Endpoint: /api/v1/build_public_tmp/<flow_id>/flow

Manual Exploitation

The browser request to the public playground was captured and modified. The flow contained a TextOperations-yvwhG node whose Python code was modified so that the final get_message() method executed shell commands using Python. 

def get_message(self) -> Message:
    import os
    return Message(text=os.popen("id").read())

The first proof of execution returned:

uid=33(www-data) gid=33(www-data) groups=33(www-data)

Reverse Shell

A Bash reverse shell was triggered through the modified Langflow component and caught on the attacker machine. This produced a shell as www-data in /var/lib/langflow.

Lessons Learned

  • Certificate SANs and vhost hints can reveal the real application surface.
  • Public AI workflow endpoints should be treated as high-risk if they accept custom code or dynamic components.
  • Environment variables frequently contain service credentials and should be reviewed after obtaining a service-account shell.
  • Password reuse between application accounts and Linux users can turn app compromise into SSH access.
  • JWT implementations must never accept alg:none.
  • Tool registration APIs that accept arbitrary code are effectively remote execution primitives.
  • Kubernetes nodes/proxy permission can be extremely dangerous, especially when privileged monitoring pods mount the host filesystem.
