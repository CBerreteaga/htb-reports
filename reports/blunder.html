Summary

Blunder is an Easy difficulty Linux machine featuring a Bludit CMS instance running on port 80. Initial enumeration revealed a web application built on Bludit, with an exposed admin panel and several interesting files including robots.txt and todo.txt. Using directory brute forcing, we discovered user references and the admin login page. The system was vulnerable to a brute-force protection bypass affecting Bludit 3.9.2, which allowed credential discovery for user fergus. After gaining access to the admin panel, we identified a known file upload and directory traversal vulnerability leading to remote code execution. This resulted in a www-data shell. Further enumeration revealed password hashes in the Bludit database, which were cracked to obtain credentials for user hugo. Finally, privilege escalation was achieved via a vulnerable sudo version (CVE-2019-14287), resulting in root access.

Initial Foothold

Directory brute forcing with Gobuster revealed /admin, /todo.txt, and several hidden resources. The /todo.txt file hinted at a user named fergus. The login page was protected by brute-force mitigation, but this was bypassed using a known Bludit vulnerability (CVE-2019-17240) involving forged X-Forwarded-For headers. A CeWL-generated wordlist was used to successfully brute-force credentials, granting access to the admin panel. A known Bludit file upload and directory traversal vulnerability was then exploited to achieve remote code execution, resulting in a www-data shell.

Privilege Escalation

Local enumeration revealed a password hash for user hugo in the Bludit database. The hash was initially not crackable with rockyou.txt, but was successfully recovered using external hash lookup services, revealing the password. After switching to user hugo, sudo privileges were inspected and revealed an outdated sudo version (1.8.25p1). This version was vulnerable to CVE-2019-14287, allowing privilege escalation via sudo -u#-1, which bypasses restrictions and spawns a root shell.

Vulnerabilities / Misconfigurations

The primary vulnerabilities included Bludit CMS version 3.9.2 running with known authentication bypass issues, insecure file upload functionality, and outdated sudo (1.8.25p1) vulnerable to CVE-2019-14287. Combined, these allowed a full chain from unauthenticated access to root compromise.

Defensive Takeaways

Organizations should ensure CMS platforms are regularly updated, disable or restrict file upload functionality, implement proper brute-force protections that cannot be bypassed via header spoofing, and keep sudo updated to patched versions. Proper logging and intrusion detection would also help detect exploitation attempts.

Lessons Learned

This machine demonstrates the importance of full attack surface enumeration. Small findings such as robots.txt, todo files, and CMS version leaks can chain into full system compromise. It also highlights how multiple small vulnerabilities (information disclosure, weak auth protection, and outdated binaries) combine into a full exploit chain.
